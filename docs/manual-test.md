# Phase 0 手動確認

この文書は、CIやNode.jsテストでは確認できないChrome・OBS・Twitch実機経路を確認するためのものです。

## 前提

- Google Chrome 138以降
- OBS Studio 28以降
- OBSの「ツール → WebSocketサーバー設定」でWebSocketサーバーを有効化
- WebSocketパスワードを設定
- Twitchへテスト配信できる環境

## 拡張の読み込み

1. `chrome://extensions` を開く。
2. 「デベロッパーモード」をONにする。
3. 「パッケージ化されていない拡張機能を読み込む」で、このリポジトリのルートを選ぶ。
4. ツールバーの拡張アイコンを押し、サイドパネルが開くことを確認する。

## 成立性チェック

- [ ] マイク権限が「確認」の状態で「更新・許可」を押すと、許可用タブ（mic-permission.html）が開き、マイク許可ダイアログが表示される
- [ ] 許可用タブで「許可」を選ぶと、成功メッセージの後にタブが自動で閉じ（閉じない場合は手動で閉じる案内が出る）、サイドパネルのマイク欄が「許可済み」になりマイク一覧にラベル付きで表示される
- [ ] 一度許可した後に「更新・許可」を押し直しても、許可用タブは開かずにそのまま一覧が更新される
- [ ] 許可用タブが開いている間に「更新・許可」をもう一度押しても、2つ目のタブは開かず既存タブがフォーカスされる
- [ ] 許可用タブをダイアログに答えずに閉じると、サイドパネルに警告ログが出て、タブが自動で再度開かない
- [ ] 許可用タブで「ブロック」を選ぶと、タブに設定変更手順が表示されたまま残り、サイドパネルのマイク欄が「ブロック中」になる
- [ ] chrome://settings/content/microphone で「ブロック」にした状態で「更新・許可」を押すと、許可用タブを開かずに設定変更手順がログに表示される
- [ ] 許可用タブが開いている間にサイドパネルを閉じても、タブ単体で許可を完了でき、次回サイドパネルを開くとマイク欄が「許可済み」になる
- [ ] マイク一覧に配信用マイクが表示される
- [ ] Chromeの欄が「対応」になる
- [ ] 翻訳の初回準備・ダウンロードが開始できる
- [ ] OBS WebSocketへパスワード付きで接続できる
- [ ] OBSが配信中の場合、「テスト字幕」で英語字幕を送れる
- [ ] 日本語で話すと途中認識と確定日本語が表示される
- [ ] 確定日本語が英訳され、TwitchのCCに英語だけが表示される
- [ ] OBS上の指定マイクをミュートすると字幕送信が止まる
- [ ] OBS配信を停止すると字幕送信が止まる
- [ ] サイドパネルを閉じるとマイク利用が止まる
- [ ] SpeechRecognition終了後に自動再開する
- [ ] 2時間連続運用しても古い字幕がまとめて流れない
- [ ] 長い発話が複数字幕に分かれた場合、前の字幕が読み切れる間隔で送られる（`segmentIntervalMs`）
- [ ] 句点なしで長く話し続けると、発話が確定する前に最初の英語字幕が表示される（`interimFlushChars`既定40）
- [ ] 上記の発話が確定した後、末尾に重複・崩れた字幕が続けて出ない
- [ ] 短い発話（40文字未満）はこれまでどおり確定後に1回だけ送られる
- [ ] `interimFlushChars`を0にすると、これまでどおり確定するまで送られない
- [ ] 「このデバイスにパスワードを保存する」をONにして再保存 → Chromeを再起動 → パスワード欄に再入力なしで復元され、そのままOBSへ接続できる
- [ ] 上記をONにした状態でOFFへ戻す → Chromeを再起動 → パスワード欄が空で復元される（ローカル保存が消えている）

## 言語選択UI・多言語対応（issue #6以降の追加分）

- [ ] 「認識言語」「翻訳先」がテキスト入力ではなく選択式（`<select>`）になっている
- [ ] 一覧にない言語コードを保存済みの状態で拡張を開くと、値が消えずに「その他（手入力）」＋テキスト欄に復元される
- [ ] 「その他（手入力）」を選ぶとテキスト欄が現れ、値を入力できる。別の言語を選び直すとテキスト欄が隠れる
- [ ] 入れ替えボタン（⇄）を押すと認識言語と翻訳先が入れ替わる
- [ ] `en-GB`を認識言語にした状態で入れ替え→再度入れ替えすると`en-US`に変化する（既知の非対称挙動。想定どおりであることを確認）
- [ ] 言語ペアを変更すると、開始ボタンを押す前に利用可否（利用可能・要ダウンロード・利用不可など）がその場に表示される
- [ ] 利用不可と表示された状態でも「CCを開始」は押せる（事前表示は目安であり、実際のエラーは開始時に別途出る）
- [ ] 認識言語と翻訳先を同じ言語にすると、API呼び出しなしで「同じ言語です」旨の表示になる
- [ ] Chromeの表示言語を英語に切り替えて拡張を再読み込み（Chrome再起動が必要な場合あり）すると、サイドパネルのラベル・ボタン・イベントログが英語表示になる。日本語に戻すと日本語表示に戻る
- [ ] 上記の言語切り替え後も、既存の「CCを開始」〜OBS送出フローが問題なく動作する

## 認識モード・自動句読点・翻訳前補正（認識強化の追加分）

- [ ] 「認識モード」が`conversation`（既定）で保存・復元される
- [ ] `conversation`と`command`で同じ文章を話し、認識精度・確定までの遅延に差が出るか記録する（`command`が従来挙動）
- [ ] 未対応Chrome（属性なし）では設定を変更しても開始時にエラーにならず、従来どおり認識する
- [ ] 「自動で句読点を補う」ON時、句読点なしで話しても日本語プレビューに句読点が付く。OFFで付かない
- [ ] 置換JSONに認識原文へマッチする語（例: `{"あずま": "Azuma"}`）を入れ、その語を話すと、日本語プレビュー・英訳の両方に補正が反映される
- [ ] 上記の補正が`interimFlushChars`の途中確定チャンクにも適用される（途中プレビューで確認）

## 途中停止・再開（認識の堅牢化の追加分）

- [ ] 30秒以上話さずに沈黙した後、再度話し始めると数秒以内に認識が再開する
- [ ] 配信中にマイクを一度抜いて（またはOSでデバイスを切り替えて）戻すと、音声入力が復帰する
- [ ] サイドパネルやブラウザを別アプリへ切り替えて数分後に戻っても、認識が止まったままになっていない（戻った後も新しい発話がプレビューに出る）
- [ ] 認識の停止・再開時、ステータスが「再開待ち」になり、エラーが出る場合はイベントログの文言を記録する
- [ ] 90秒の沈黙制限で再開が入った場合、誤って字幕が送られないこと（再開自体は無音のため字幕は出ない想定）
- [ ] マイクを許可した状態でサイドパネルを閉じて開き直すと、ステータスが「未許可」ではなく「許可済み」と表示される（開き直し直後は「確認中」→「許可済み」）
- [ ] 一度「ブロック中」にして開き直すと「ブロック中」が表示され、「許可」へ戻すと「許可済み」に変わる

- 選択したマイクが実際の認識入力に使われたか

- 連続字幕の安全な送信間隔
