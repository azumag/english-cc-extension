# Phase 0 手動確認

この文書は、CIやNode.jsテストでは確認できないChrome・OBS・Twitch実機経路を確認するためのものです。

## 前提

- Google Chrome 138以降
- OBS Studio 28以降
- OBSの「ツール → WebSocketサーバー設定」でWebSocketサーバーを有効化
- WebSocketパスワードを設定
- Twitchへテスト配信できる環境

## 拡張の読み込み

1. `chrome://extensions` を開く。
2. 「デベロッパーモード」をONにする。
3. 「パッケージ化されていない拡張機能を読み込む」で、このリポジトリのルートを選ぶ。
4. ツールバーの拡張アイコンを押し、サイドパネルが開くことを確認する。

## 成立性チェック

- [ ] 「更新・許可」でマイク許可ダイアログが表示される
- [ ] マイク一覧に配信用マイクが表示される
- [ ] Chromeの欄が「対応」になる
- [ ] 翻訳の初回準備・ダウンロードが開始できる
- [ ] OBS WebSocketへパスワード付きで接続できる
- [ ] OBSが配信中の場合、「テスト字幕」で英語字幕を送れる
- [ ] 日本語で話すと途中認識と確定日本語が表示される
- [ ] 確定日本語が英訳され、TwitchのCCに英語だけが表示される
- [ ] OBS上の指定マイクをミュートすると字幕送信が止まる
- [ ] OBS配信を停止すると字幕送信が止まる
- [ ] サイドパネルを閉じるとマイク利用が止まる
- [ ] SpeechRecognition終了後に自動再開する
- [ ] 2時間連続運用しても古い字幕がまとめて流れない

## 端末確認

- [ ] Twitch PCブラウザでCCボタンが表示される
- [ ] iPhoneで字幕をON/OFFできる
- [ ] Androidで字幕をON/OFFできる
- [ ] VODに字幕が残るか確認し、READMEへ結果を追記する

## 記録する項目

- Chrome / OBSのバージョン
- 選択したマイクが実際の認識入力に使われたか
- 発話終了から字幕表示までの概算遅延
- CEA-608で崩れた文字や記号
- 1字幕あたり安全に表示できた文字数
- 連続字幕の安全な送信間隔
